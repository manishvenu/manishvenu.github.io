# Extending the site

Ideas for making the site do more than show text, roughly in the order you should reach for them.

**Short version: you don't need your Tailscale server right now.** Plots from data, live-looking numbers, interactive models and playable games all work on a static GitHub Pages site (sections A and B). A server (section C) only earns its keep when visitors need to *send* something to you (a form, a leaderboard), or when the work needs private data or more compute than a browser has.

---

## A. Python runs when the site is built (no server)

### A1. Python code in a page

Any `.qmd` can contain Python. It runs during `quarto preview`/`render`, and the output (plots, tables) goes into the page.

````markdown
---
title: "Mono Lake levels"
---

```{python}
#| echo: false          # hide the code, show only the plot
import pandas as pd
df = pd.read_csv("../data/mono_lake.csv", parse_dates=["date"])
df.plot(x="date", y="level_ft")
```
````

Add any packages you import to `environment.yml`.

**Important: freeze.** GitHub's build machine doesn't have your Python packages. Add this to `_quarto.yml`:

```yaml
execute:
  freeze: auto
```

Now code runs only on your machine when the file changes, and the results are saved in a `_freeze/` folder. Commit `_freeze/` and GitHub just reuses the saved output.

Interactive plots work too: use `plotly` instead of matplotlib and the chart is zoomable/hoverable in the browser, still with no server.

### A2. Pages generated by a Python script

Quarto can run a script before every build:

```yaml
# _quarto.yml
project:
  pre-render: scripts/make_projects.py
```

The script can write `.qmd` files. For example, call the GitHub API, and write a `projects/<repo>.qmd` for every repo tagged `portfolio`, with star counts in the description. You only maintain the script; the page keeps itself up to date.

### A3. Scheduled rebuilds ("looks live")

Rebuild every morning, so anything from A1/A2 pulls fresh data. Add to `.github/workflows/publish.yml`:

```yaml
on:
  push:
    branches: main
  schedule:
    - cron: "0 12 * * *"    # every day at 12:00 UTC
```

If the build fetches data itself, it needs Python on GitHub's machine: add a step `pip install -r requirements.txt` before publishing, and don't freeze those pages. Good for: lake levels from USGS, your GitHub activity, itch.io stats.

## B. Python runs in the visitor's browser (no server)

### B1. Shinylive: a Python app inside a page

[Shiny for Python](https://shiny.posit.co/py/) apps can run entirely in the browser (via WebAssembly). Sliders, dropdowns, plots that react; no server.

```bash
quarto add quarto-ext/shinylive
pip install shinylive
```

````markdown
---
filters: [shinylive]
---

```{shinylive-python}
#| standalone: true
from shiny import App, ui, render
app_ui = ui.page_fluid(ui.input_slider("n", "Years", 1, 50, 10), ui.output_text("out"))
def server(input, output, session):
    @render.text
    def out(): return f"Forecasting {input.n()} years ahead"
app = App(app_ui, server)
```
````

Good fit for a small MonoCopula demo. Limits: first load is slow (downloads Python, a few seconds), and only pure-Python/common scientific packages work (numpy, pandas, scipy, matplotlib are fine).

### B2. Observable JS cells

Quarto has reactive JavaScript cells built in (` ```{ojs} `). Good for interactive charts from a CSV with filters. Optional; Shinylive is the Python route.

### B3. Games

Unity WebGL and itch.io HTML5 embeds already work (README → "Make a game playable in the browser").

## C. A real server on your Tailscale machine

### When it's worth it

- Visitors **submit** something: contact form, guestbook, game high-score leaderboard.
- **Private data** or API keys that can't be in a public repo.
- **Heavy compute** on demand (run a real model run when someone clicks a button).
- Something **always running** (a bot, a live data feed).

None of these exist on the site today.

### How it would work

1. Write a small API on the machine, e.g. FastAPI:

   ```python
   # server.py   ->  run with: uvicorn server:app --port 8000
   from fastapi import FastAPI
   from fastapi.middleware.cors import CORSMiddleware
   app = FastAPI()
   app.add_middleware(CORSMiddleware, allow_origins=["https://manish.venumuddula.com"], allow_methods=["*"])
   scores = []

   @app.post("/scores")
   def add(name: str, score: int):
       scores.append((name, score)); return {"ok": True}

   @app.get("/scores")
   def top(): return sorted(scores, key=lambda s: -s[1])[:10]
   ```

2. Make it reachable from the internet. Tailscale normally only lets *your* devices in, so you need one of:
   - **Tailscale Funnel**: `tailscale funnel 8000`. Gives a public HTTPS URL like `https://yourbox.tailnet-name.ts.net`. Easiest. It only uses `*.ts.net` names, not your own domain.
   - **Cloudflare Tunnel**: if you want `api.venumuddula.com`. Needs the domain's DNS on Cloudflare.
3. Call it from a page on the static site:

   ```html
   <ul id="scores"></ul>
   <script>
   fetch("https://yourbox.tailnet-name.ts.net/scores")
     .then(r => r.json())
     .then(rows => document.getElementById("scores").innerHTML =
       rows.map(([n, s]) => `<li>${n}: ${s}</li>`).join(""));
   </script>
   ```

   Or embed a whole app (Shiny server, Django, Streamlit) with an `<iframe>`.

### Things to know first

- The feature is only up when your machine is on. Design pages so they still look fine if the request fails.
- Anything public gets probed by bots: keep packages updated, validate input, never expose more than the one port.
- Keep the main site static. Use the server only for the one feature that needs it.
